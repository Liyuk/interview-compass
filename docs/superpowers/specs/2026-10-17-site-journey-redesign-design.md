# 全站交互与用户动线重新设计

状态：待用户审阅。取代旧 wiki 规范中「内页移除顶栏」「所有内页常驻全站知识侧栏」两项决定。

## 任务与成功标准

用户要求分析整个站点的交互、用户动线，然后重新设计实现。直接反馈是截图中的六入口顶栏在多页面之间消失，以及此前出现的页面抖动和手册显示问题。本轮覆盖首页、目标路径、题库、搜索、题单、题目详情、分类、能力与阶段、方法、Starlight 手册及全部英文对应页面。

目标用户是准备面试、晋升和承担技术管理责任的工程师，以及使用问题进行访谈的人。主要任务是找到相关问题、理解问题意图与证据、连续阅读与比较。保留现有题目、来源、路由与静态部署，遵循 PRODUCT.md 的工程师定位及不提供标准答案和自动评分的边界。

成功表现：任何页面可跨板块跳转；新用户无需先做配置即可看内容；找题页面让位给结果；阅读页面能继续当前任务；导航、语言和目标上下文一致；初次加载和菜单操作不造成意外正文位移。

## 当前证据与问题

核查基础为独立 worktree `codex/wiki-knowledge-experience`，起始 HEAD `0ef068f`。主工作区存在尚未提交的手册编辑，实施时不能覆盖。

1. `SiteMasthead.astro` 的 `{!wiki && ...}` 不为内页渲染主导航。`SiteLayout.astro` 对非首页传入 wiki，Starlight Header 也传入 wiki。2026-10-17 的真实浏览器快照确认首页有六入口，题库页 banner 没有主导航。这是已证实的设计和实现缺陷。
2. `SiteLayout.astro` 所有内页套三栏知识框架，题库同时渲染全站知识目录、主筛选与高级筛选；搜索也沿用同一侧栏。读者需要在多个层级之间识别主操作。布局存在已确认重复职责；具体改善程度需实施后浏览验证。
3. `target-selector.ts` 初始加载角色后调用 needsTargetPrompt/openEditor。新浏览器首页和题库快照均出现自动打开的目标选择框。用户尚未看到内容就被要求选择。
4. `ReadingJourney.astro` 已实现结果来源、滚动及 details 恢复，但 `readingReturnPath` 拒绝目标参数和部分分页、阶段路径。目标上下文相关 URL 可能没有阅读返回入口；需通过用例验证和修复。
5. `QuestionView.astro` 有返回链接和相关文章，但页尾优先导向精选题单、目标路径、能力分类，没有优先继续本次来源的动作。
6. Starlight Header 固定 176/196px；菜单脚本另写 404px，starlight.css 又叠加主内容 margin 和目录 top。高度与内容、语言、断点耦合，是导航调整时的风险来源；不能将这一源码风险当作所有抖动的已证实原因。
7. 首页目前同时存在主目标按钮、已知需求入口、使用目标、精选题单和方法引导。它们都有用途，但目标路径与岗位阶段目标的含义需要区分，首屏要建立一个清楚主动作。

## 方案选择

A（采用）：统一全站顶栏，按任务选择页面布局。保留既有视觉识别，重做内容与导航职责。操作页为宽结果区，阅读页为文章加目录，分类和阶段页提供本板块局部导航。

B：统一顶栏加所有页面完整知识侧栏。保留跨站导航但重复入口多，找题区域继续被挤占。

C：统一成文档站，以侧栏承担主导航。适合纯手册，但不符合用户明确要求的全站顶栏与混合找题流程。

## 导航与页面框架

全站共享同一 SiteMasthead 和同一份六入口定义：目标路径、面试题库、提问方法、使用说明、分类索引、阶段能力。品牌回首页；语言切换与准备目标始终可达。主入口当前板块用文字语义和标记表达；后代路由也能识别所属板块。页头不由页面类型决定是否存在。

宽屏完整显示入口。空间不足时依据统一断点整体收为「站点导航」，不挤压英文标签或产生页面横向溢出。菜单作为可关闭浮层，Escape 关闭并返回触发器，语义展开状态正确，键盘可达；无脚本仍有静态导航路径。小屏局部目录与本页目录分别标注，不再额外给每页放全站知识树。搜索为固定布局中的共享控件，建议结果浮层不推正文；避免英文和目标标签变化导致页头跳高。

页面框架由明确的 route presentation 配置派生，不由 CSS 猜测内容。配置区分 home、discovery、article、section；可选局部导航和 outline。路由与标签仍使用现有 RouteRef/pathFor，本轮不改 URL。

| 页面族 | 内容结构 | 导航职责 |
| --- | --- | --- |
| 首页 | 产品用途、搜索、按目标准备主入口、精选题单与分类入口 | 全站顶栏，减少同一任务重复号召 |
| 目标路径 | 使用情境入口、每条路径的具体下一步和相关题目 | 区分「使用情境」与「岗位/阶段准备目标」 |
| 题库、搜索 | 标题、当前目标、筛选/关键词、条件摘要、计数、结果、分页 | 不显示全站知识侧栏，不为短列表生成空目录 |
| 题单/路径详情 | 目的、适用范围、有顺序的题目、关联方法 | 题目链接可返回当前集合 |
| 题目详情 | 返回本次来源、问题、意图、背景与证据、关系与来源 | 右侧本页目录；页尾优先返回当前来源，再看相关问题 |
| 分类索引/详情 | 独立分类维度、有效计数、列表/相关题目 | 按当前板块提供局部导航，不把独立分类伪装父子树 |
| 阶段能力系列 | 模型概览、阶段/维度/岗位视角及匹配题目 | 本板块导航，明确能力分类与责任阶段差异 |
| 方法/使用说明 | 连贯长文、章节锚点、相关题目入口 | 局部章节导航和唯一一份本页目录 |
| 404 | 清楚说明、搜索和回题库 | 同一全站顶栏和语言入口 |

视觉沿用现有品牌、暖白、深色文字、蓝色链接和红色当前位置。重点重做层级、空间和交互，不更换品牌。正文有可读行宽；操作页允许更宽结果区；短页面不预留空目录列。

## 核心用户动线

### 首次进入与直接访问

打开首页或任意分享链接立即看到内容，不自动弹出准备目标对话框。页头右上角固定尺寸状态入口标为「准备目标」或当前岗位阶段；不再显示搜索下方的全宽目标栏。点击状态入口展开浮层，显示当前目标、题目数量、切换目标、查看全部题目、阶段要求及链接目标/存储提示。未选择时浮层显示全部题目的状态。浮层不占正文布局空间，支持外部点击、Escape 和焦点离开关闭。目标设置由用户主动触发。保留可跳过、关闭、修改、查看全部、加载失败重试及本地存储不可用提示，不强制注册。

首页主动作帮助不确定的人按目标准备；知道内容的人可直接搜索、进全量题库或分类。已有目标的人可直接看到适用状态；不虚构学习进度。

### 搜索与筛选到题目

搜索输入、提交、清空、建议和全部结果行为一致。空查询明确提示输入或进入题库；无结果提供清除条件/减少关键词；索引失败提供重试与可用题库入口。目标筛选影响结果时明确显示，避免读者误以为内容不存在。

题库维持已有独立筛选、URL 分享与分页，显示当前筛选和清除操作。小屏高级筛选折叠，结果不被长知识树顶到屏幕下方。分类、题单和路径都落到真实内容或可理解的结果集合。

### 阅读与继续

从结果/集合进入题目后，顶部和页尾提供一致的「返回本次结果/题单」。返回保留语言、关键词、筛选、页码、目标上下文、展开状态与滚动位置。直接访问无来源时有可见的回题库兜底，不依赖浏览器历史推断。

仅接受同站同语言的安全来源 URL；支持现有合法目标参数与分页路径，不放宽到任意跳转。相关文章不覆盖有效来源；语言切换保持对应题目与适用参数。模型页、分类页到题目的来源也应可恢复。

### 理解方法与阶段

用户从题目可以理解共用阅读框架与逐题复核状态差别，查看方法和阶段要求后能通过全站导航回题库。手册采用相同页头、搜索和语言控件，保留 Starlight 文章锚点及本地化，不出现重复菜单和目录。

## 布局稳定与可访问性

静态 HTML/CSS 先决定主要结构和断点；避免脚本再移动整块侧栏、隐藏正文或改变页头高度。目标状态预留稳定空间并正确处理加载失败。Starlight 优先使用自然布局和统一共享尺寸约束；确需测量时以实际高度作为单一来源，不能再堆固定像素补偿。

宽屏、平板、小屏均检查长英文标签、目标摘要、菜单、搜索建议、目录和锚点。一个 h1、跳正文、明确 landmark 标签、当前项 aria-current、可见焦点、44px 主要触控目标；打开浮层管理焦点并支持 Escape。锚点内容不被页头遮挡。

## 实施边界与顺序

1. 建立共享导航及路由呈现策略，恢复全部页面顶栏。
2. 重构响应式菜单和 Starlight 适配，消除固定高度补丁。
3. 按页面族应用操作/阅读/板块布局，移除全站知识树重复。
4. 调整首页与主动目标选择流程、搜索状态说明。
5. 补齐来源安全校验和连续阅读闭环，覆盖目标、分页及双语。
6. 浏览器验证、构建与现有检查，更新现有 PR 的说明及截图。

实施前比较主工作区未提交手册修改与 worktree，保留用户内容。已有 URL、数据接口、过滤语义、来源署名、许可与静态 GitHub Pages 基础路径均保持有效。

## 验证与交付证据

- 静态路由清单检查全部中英文 HTML 页面存在共享主导航和正确所属板块；不以几个截图代表全站覆盖。
- 浏览器验证首页→目标→题库→筛选第2页→题目→返回；搜索→题目→返回；分类/阶段→题目→返回；方法↔手册→切语言；直达题目→题库。验证 URL 和恢复状态，记录截图。
- 新存储上下文打开首页、题库、题目、手册均不自动打开目标框；主动打开、修改、查看全部和关闭正常。
- 代表页面在 390/768/1024/1440px 检查，额外检查 320px 溢出、英文和键盘。全站导航与局部目录可区分；短页面无空目录；菜单不推正文。
- 生产构建检查首屏稳定性；记录布局偏移来源，区分用户主动展开与意外加载偏移，不将开发服务器热更新当作发布站证据。
- 运行既有类型、内容、单元、构建、大小和端到端检查。针对路由呈现、来源安全、首次目标选择与跨页导航的实际风险补回归，避免为纯样式机械新增测试。
- PR 描述围绕最终全站动线重写，列出验证证据和仍存在的限制；本轮不自动合并。
