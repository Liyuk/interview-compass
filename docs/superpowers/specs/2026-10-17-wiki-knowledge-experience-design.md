# Wiki 风格知识站点设计规范
> **Historical record:** This document records a plan or review from its date; its framework and implementation statements are not current. See the [current architecture](../../architecture/current-state.md).


## 目标与范围

将 Interview Compass 的首页以外的全部中英文内容页面组织成更明确的知识站：读者能看出当前页面所属知识分区、沿分类层级上下浏览、跳到长文章的具体章节，并通过题目之间的分类和主题关系继续探索。首页继续保留现有面向任务的入口，不纳入本次视觉和结构改造。

本次改造保留现有 Astro 路由、题目与分类数据、Pagefind 搜索流程、中文根路径和英文 `/en/` 路径。题目仍是主要知识对象；岗位、主题、场景、责任范围、职业轨道和能力是可交叉浏览的独立维度。界面不能把这些交叉分类伪装成单一父子树。

适用页面包括题库、搜索结果、题目详情、精选题单、目标路径、岗位/主题/场景索引及详情、能力地图、能力模型及其阶段/维度/岗位页面、提问框架、分类索引，以及 Starlight 渲染的中英文《使用说明》。数据 JSON 接口、静态许可文本与首页不作为知识文章改造；其现有链接和产物不变。

## 推荐方案

采用双适配器、统一信息架构的 wiki 阅读框架：普通 Astro 页面沿用 `SiteLayout` 并增加共享知识侧栏、页内目录和文章关系区；Starlight《使用说明》继续使用 Starlight 正文、响应式目录和本地化能力，通过 Starlight 侧栏/页头适配接入相同的知识导航与视觉规则。不要把题目迁移到 Markdown，也不要求所有普通页面迁移到 Starlight。

该方案以当前共享布局和 route/taxonomy 数据为接缝，覆盖面比单独配置 Starlight sidebar 更完整，同时避免改写结构化题目记录、稳定 URL、筛选和现有题目来源关系。两套渲染器共享相同的分区顺序、命名和视觉 token；不复制整套导航内容源。

## 页面框架与导航

### 全局页头

- 首页维持现状。
- 其他页面保留品牌、搜索、目标选择和语言切换；将原来承担内容目录作用的导航收敛到 wiki 侧栏。桌面上页头保持紧凑，避免与侧栏重复列出全部入口。
- 小屏继续提供可键盘操作、可见焦点且带展开状态的站点导航控件。搜索、目标选择和语言切换保持可发现。

### 知识侧栏

桌面侧栏常驻于文章左侧，允许长列表区域独立滚动；站点页头之后显示当前语言的知识目录。目录分区固定为：

1. **题库**：全量题库、精选题单、按目标浏览。
2. **分类浏览**：岗位、主题、场景、能力地图入口。
3. **能力与阶段**：能力模型、阶段标准、阶段维度、岗位阶段视图、跨公司职级映射。
4. **方法与说明**：提问框架、使用说明。

当前页面所属分区高亮，并展开必要的父节点及有限层级的邻近项。能力地图显示当前能力域及其叶子节点；岗位、主题、场景详情显示其索引父项。其他独立分类不被插入能力树。侧栏不枚举数千道题，也不显示会制造横向分类关系的伪父子层级；详细标签和完整结果继续由文章正文承载。

小屏侧栏收为明确标注的导航抽屉/折叠目录，默认关闭；展开后保留相同内容顺序、当前项状态和父级回退入口。切换路由后抽屉关闭。导航可在无 JavaScript 时以可用链接呈现，交互增强不得阻断正文访问。

### 阅读区域与页内目录

- 普通内容页面使用三栏网格：知识侧栏、中心文章、页内目录。中心列保持可读行宽；长篇才展示页内目录，目录链接定位到文章中选定的二级章节。
- 短索引、搜索结果和短详情可省略空的页内目录，但仍使用同一中心文章区域和知识侧栏。
- 被列入页内目录的标题须有稳定、唯一的 HTML ID；中文和英文各自明确标题文本。目录包含仅有助于定位的实质章节，不包含卡片内的小标题、控件标题、重复元数据、导航或页面主标题。
- Starlight 页面继续使用其标题层级、章节锚点和响应式 TOC；样式、分区和导航信息与普通页面保持一致，不额外渲染重复 TOC。
- 窄屏收起右侧目录为文章顶部的“本页目录”折叠控件；保留章节锚点直达能力与焦点可见性。

### 文章内容与关系

- 类别索引页成为知识入口：保留解释性引导，清楚列出下级分类/条目、有效计数和进入相关题目的链接。
- 分类详情页在列表附近标明该页面使用的筛选视角，并保留分页、筛选、目标上下文与共享 URL 行为。
- 题目详情继续突出题目、目的、背景、观察信号、上下文追问、比较和取舍、证据参考、逐题复核状态及来源。增加或明确一组“所属分类”链接，分别标识主要能力、岗位、主题、场景等可用关系；不把分类标签重复堆入主导航。
- 长文章以页内目录帮助定位；已有相关文章、来源、上/下页或返回筛选结果的功能保留并按 wiki 方式明确呈现。
- 不添加答案示例、自动评分、候选人总分、招聘建议、编辑历史或讨论等产品并不存在的 wiki 功能。

## 路由、数据和本地化

- 现有路径和稳定问题 ID 不变；中文仍位于根路径，英文仍位于 `/en/`。
- 新增导航标签通过站点现有双语词条机制提供中英文版本。语言切换仍落到同一已翻译路由，并保留现有搜索词、筛选参数、目标偏好和章节锚点传递规则。
- route 导航状态从现有 `RouteRef`、`activeNavFor`、`breadcrumbsFor` 与 taxonomy 中推导，避免页面模板各自重新实现父级关系。
- 不改变 Pagefind 构建/索引行为、题目筛选语义、收藏题单顺序、角色/阶段工具、目标上下文、内容许可和来源归属。
- 页面构建失败时不得输出没有主内容的空壳；缺少可选关系数据时隐藏相应区块，缺少导航标签时用现有路由标题回退。

## 可访问性与响应式要求

- 所有导航、目录、筛选和抽屉可用键盘操作；当前页使用语义化 `aria-current`，折叠控件同步 `aria-expanded`，标题层级从一个页面 `h1` 开始。
- 页面有跳到正文链接。抽屉打开时管理焦点，Escape 关闭并返回触发按钮；菜单不会覆盖或遮断页面主内容而没有可关闭机制。
- 320px 及以上视口无横向溢出；宽屏文章行长受限，题库表格和矩阵有明确的小屏处理。
- 遵循现有暖白底色、深色文字、红色当前位置、蓝色链接和 Starlight/Radix 设计约定；明确标签和结构，不依赖颜色单独表达状态。

## 验收标准

1. 每个非首页中英文 HTML 内容路由都显示统一知识侧栏、清晰当前位置和文章阅读区域；首页维持当前任务入口构成。
2. 侧栏入口覆盖题库、精选题单、目标路径、岗位、主题、场景、能力地图、能力模型、提问框架与使用说明，并能准确标识对应路由。
3. 能力域/叶子、岗位、主题、场景、阶段模型及阶段细分页面可从目录向上回退并进入同组页面；独立 facet 维度保持相互独立。
4. 长文章提供无重复、可直达的本页章节目录；短页面不显示空目录；Starlight 页面目录与自定义页面目录视觉一致且只出现一次。
5. 题目条目中的原有分类链接、题库分页和筛选 URL、搜索行为、目标偏好、语言切换和返回阅读路径继续工作。
6. 中文与英文目录内容、当前状态、面包屑及章节链接都匹配各自语言路由；所有现有 URL 保持不变。
7. 桌面、平板和 320px 小屏都能访问完整正文和导航；键盘焦点清晰、折叠状态正确、无横向页面溢出。
8. 数据接口、许可文本、内容来源与部署目录不因知识导航改造而改变。

## 验证范围

实现后构建整个静态站点，并检查生成的全部 HTML 内容路由及资源链接；在浏览器中核对中英文各类代表路由（首页、题库/搜索、索引、分类详情、题目详情、能力树节点、阶段节点、框架与 Starlight 使用说明）的桌面和小屏呈现。验证侧栏当前项、面包屑、目录锚点、语言切换、题目关系链接和筛选/返回路径。运行仓库已有与内容路由、无障碍、静态构建有关的检查，并记录任何不适用或既有失败。
