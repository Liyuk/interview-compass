# 准备指南与题库的信息架构方案

状态：设计提案与自审完成，待书面方案审阅；尚未实施。
日期：2026-10-19
依据：用户提出“首页 → 站点说明、定位画像、理解角色要求 → 方法与问题清单”，并要求把使用说明、提问方法、阶段能力、分类聚合为一个板块。

## 1. 设计目标与边界

让第一次访问的人理解如何准备，并帮助熟悉站点的人快速进入题目。主导航明确为“首页 / 准备指南 / 面试题库”，全站搜索为持续可见的工具入口。中文名称为“准备指南”，英文建议为“Preparation guide”。

本轮是阅读与发现的信息架构调整。问题仍是主要内容单元；方法、角色要求、分类原则帮助用户理解和使用题目。现有能力模型与逐题分析的复核标识继续表达各自真实覆盖范围。

成功标准：用户能找到起点、知道当前阅读位置、理解岗位与阶段的意义、进入可解释的问题集合，并从问题返回原来的集合或指南。首次阅读是推荐路径，可以跳读；直接链接和搜索访问保持完整可用。

## 2. 方案选择

| 方案 | 效果 | 成本与判断 |
| --- | --- | --- |
| 仅把原有六入口放入“更多”菜单 | 改动较小 | 仍然把理解模型、选择目标、浏览题目交给用户自己串联，不能满足本次目标 |
| 准备指南 + 面试题库，搜索为公共工具 | 阅读与行动各有明确入口，可复用现有页面 | 推荐；需要同步板块归属、面包屑、目录、搜索和继续阅读 |
| 首次访问强制完成定位向导 | 顺序明确 | 妨碍搜索与外链访客；用户尚未理解阶段时容易误选；不采用 |

## 3. 全站结构与页面归属

### 顶部导航和公共工具

- 首页：站点目的、从指南开始、直接找题、返回上次准备方向的入口。
- 准备指南：解释站点、能力框架、定位方向、角色要求、使用方法和分类。
- 面试题库：全部已发布题目、组合筛选、精选题单、单题阅读与本次题单。
- 全站搜索：固定顶栏入口，保留可分享结果页。桌面可直接输入，手机保留有文字替代的搜索按钮与可聚焦输入。搜索同时覆盖指南、方法、能力参考和题目。
- 准备目标状态与语言切换：公共工具，不作为内容板块。

全站搜索是独立工具界面：顶栏不误标为题库或准备指南；左侧为内容范围/结果筛选，保持同一布局外壳。打开结果后，目标文章进入自己的板块，并保留搜索来源。

### 准备指南的左侧目录

目录按以下阅读顺序分组。第一层是少量稳定分组，岗位、阶段、主题等大量条目在对应组中按需展开。

| 顺序 | 分组/文章 | 使用的真实内容 | 到下一步的动作 |
| --- | --- | --- | --- |
| 1 | 从这里开始 | 精简后的现有使用说明：用途、边界、推荐读法、怎么使用一题 | 理解能力框架；熟悉本站者可直接找题 |
| 2 | 理解能力框架 | 八个能力域的概览、主能力与交叉维度的区别 | 查看角色与责任阶段 |
| 3 | 确定准备方向 | 岗位、目标阶段、求职/晋升/面试官等使用场景的解释 | 查看选定角色要求，或先探索全部 |
| 4 | 理解角色要求 | 岗位阶段模型、责任范围、证据要求；完整矩阵、评价维度、职级映射为深入参考 | 看准备方法；查看匹配题目 |
| 5 | 提问与准备方法 | 现有面试官追问、候选人经历组织、反向尽调等方法内容 | 进入相应场景的题单或筛选结果 |
| 6 | 分类与查阅 | 分类索引、能力地图、岗位/主题/使用场景索引及边界说明 | 浏览分类内题目，或进入题库组合条件 |

指南首页是阅读路线和各组摘要，不把完整使用说明、完整能力矩阵和全部分类同时铺开。文章提供阅读顺序与下一步，参考页保留按需查阅方式。

“开始准备”是指南末尾的行动区，不为了凑齐步骤再制造一篇内容重复的文章。

### 分类归属的明确决定

分类索引及现有能力/岗位/主题/场景分类页面，统一归入准备指南的“分类与查阅”。这些页面可以保留相关题目列表和进入题库的链接。

题库保留对应维度的筛选能力，直接复用同一份分类数据。其侧栏不再复制完整指南分类树，可提供“了解分类”链接。分类说明与筛选值需要互相链接，但不复制一套题目或分类内容。

这是对上一轮口头方案的补充：用户要求分类聚合到指南，因此分类页面自身也应有明确的指南归属；实际筛题能力继续在题库提供。

### 题库左侧目录

稳定保留“全部题目 / 精选题单 / 本次题单”入口，当前文章与题单在相应位置标识。单题页的永久能力归属通过“知识归属”链接进入指南的分类页；单题页本身归属题库。

本次题单使用现有本地集合能力，入口必须能在题库总览、单题和题单页找到。其空状态说明如何添加题目，存储失败时说明当前页保存范围。若只复用现有页内面板，则该入口链接到固定面板锚点；不伪装成尚未实现的独立页面。

## 4. 用户动线与目标状态

### 首次访问

首页 → 从这里开始 → 能力框架概览 → 理解岗位与阶段 → 确定/确认准备目标 → 查看角色要求 → 提问与准备方法 → 匹配题目或精选题单 → 有序阅读。

“能力框架概览”先解释能力与责任，再让用户对号入座；完整矩阵、映射表和全部阶段描述属于深入参考，不作为必经关卡。指南里的阅读顺序不代表必须读完才能进入题库。

### 用户角色与任务

- 候选人：选择准备承担的岗位与责任范围，阅读相关方法，进入题目集合。
- 面试官：定位被评估岗位的要求，阅读取证和追问方法，选择面试题单；界面明确“本次评估目标”，避免误解为面试官自己的当前职级。
- 晋升准备者：选择目标责任阶段，阅读持续结果与归因要求，进入晋升场景清单。
- 熟悉站点的用户：首页直接进入题库、搜索或已有题单；右上角可查看和修改目标。
- 外链/搜索访客：直接读文章或题目，按需进入指南；不要求先完成定位。

### 准备目标的语义

“准备方向”是用户任务。“准备目标”状态目前仅为岗位 + 目标阶段。求职、晋升、面试官等使用场景继续作为独立筛选条件，通过 URL 进入具体结果，不悄悄合并成另一套全局画像。

当前阶段和目标阶段不能混为一个状态。第一版明确选择“希望准备/评估的岗位与责任阶段”，不新增未经定义的能力测评或自动画像。看懂模型、打开对比页不自动修改目标；用户通过明确动作应用目标。

新访客先看到内容与引导，采用非阻断的“确定准备方向”入口。右上角目标选择器仍可主动打开。首次访问弹窗与新阅读顺序冲突，需要同步调整。

继承现有状态规则：分享链接目标优先于本地默认，接收者明确采用才保存；指南与文档不会因为准备目标被隐藏；岗位/阶段与场景/主题等条件对题目取交集。没有交集时解释原因，提供改变条件、返回完整原题单或看全部的入口。

精选题单的顺序来自实际编辑内容，目标过滤后不得自动补入无关题目。本次阅读固定题目顺序，下一题/上一题与返回来源保持一致。

## 5. 方法内容与分类口径

现有方法主要是共用方法，不能仅凭选中岗位就声称已经提供了某岗位的专属方法。第一版使用“共用方法 + 真实角色要求 + 实际相关题目/题单”的组合。没有编辑内容时只提供真实参考链接，角色专属方法需要另行创作、复核并维护中英文对应。

能力主分类要求每道已发布题目有一个主要能力归属，并说明边界。MECE 是主分类的设计与审查原则，不宣称站点已穷尽所有面试知识。岗位、主题、场景、职业轨道和题型允许交叉；不能为追求形式上的互斥删除这些关系。

“八个能力域”“岗位阶段要求”“评价维度”分别回答考察什么、承担多大责任、用什么证据判断，目录和文案应解释这种关系。

## 6. 页面与交互规范

- 顶栏：始终保持相同顺序；当前内容板块只有一个高亮；搜索是工具状态。
- 左侧：指南与题库分别显示本板块目录。列表、文章与参考页都有稳定入口，手机统一“板块目录”，支持键盘、Escape 与焦点返回。
- 右侧：仅展示正文真实章节。没有章节的列表页省略本页目录，不渲染空框。
- 面包屑：表达稳定内容归属，不随搜索来源或用户目标改变。来源返回另行显示，避免动态来源冒充永久父级。
- 上一篇/下一篇：指南主线按编辑顺序继续；岗位、阶段等同组参考内容采用同组顺序。不能把面试官使用路径强制引向候选人的流程。
- 动作：概览页使用“了解能力框架”；角色页使用“以此为准备目标 / 查看匹配题目”；方法页使用真实题单名称与用途。界面不标记未经跟踪的“已完成/已掌握”。
- 搜索：共享顶栏搜索入口；结果页避免与顶栏出现两个争抢焦点的关键词输入。按“指南与方法 / 题目”分组，保留范围、条件、页码、语言及返回路径；文档组独立于目标过滤。
- 手机：全站导航、板块目录、本页目录用不同标签；按同一顺序出现，弹出板块目录时正文不跳动。
- 异常：指南正文与原生链接可静态阅读；目标数据/索引失败时可重试；暂存状态失败说明实际保存范围；未应用筛选的静态结果明确标识。
- 内容状态：逐题分析与共用阅读框架的标识可辨认；适用性复核不等于已有逐题分析。

## 7. 现有资源迁移映射

URL 下文省略部署 base 与语言前缀；中文与英文使用同样归属。

| 当前资源 | 新归属 | 页面处理 |
| --- | --- | --- |
| `/` | 首页 | 主行动指向指南；保留直接找题入口 |
| 新增 `/guide/`（提案） | 准备指南首页 | 新的路线概览，与 `/handbook/` 区分；增加对应 `/en/guide/` |
| `/handbook/` | 指南 / 从这里开始 | 精简导航说明，相关细节链接到对应文章；旧章节锚点保留可达 |
| `/capability-model/`、岗位/阶段/维度/映射页 | 指南 / 理解角色要求 | 模型总览提供易读概览，完整矩阵与映射为深入参考 |
| `/scenarios/` 与 `/paths/*/` | 指南 / 确定准备方向 | 从理解模型进入任务选择；现有路径内容作为指南文章继续提供实际清单入口 |
| `/framework/` | 指南 / 提问与准备方法 | 共用方法；按实际使用者分段阅读 |
| `/browse/`、`/capabilities/*/`、`/roles/*/`、`/topics/*/`、`/scenarios/:id/` | 指南 / 分类与查阅 | 保留分类边界与真实题目列表；链接题库对应筛选条件 |
| `/questions/` 与 `/questions/:id/` | 面试题库 | 全量已发布内容、目标与页面条件、单题阅读 |
| `/collections/` 与 `/collections/:id/` | 面试题库 | 编辑题单保留顺序；候选人反向提问指南按内容类型提供文档展示和指南交叉入口 |
| `/search/` | 全站搜索工具 | 全站范围；不再默认挂在题库板块之下 |

归属改变以导航和内容模型表达，现有 URL、题目身份、JSON 端点与查询契约继续兼容。新增指南首页不占用旧 `/handbook/`。不为新目录复制大量相同文章到新路径。

需要重点修正 `/scenarios/` 命名歧义：代码当前既用作目标路径总览，又用作场景分类路径前缀。新界面分别使用“确定准备方向”和“使用场景”，不能只从 URL 前缀推断板块/标题。

## 8. 实现约束与待编写实施计划

本节给出设计约束，不替代实施计划。

- 统一板块归属的权威映射，供顶栏、侧栏根节点、面包屑和活跃状态消费。当前 `site-navigation.ts`、`page-presentation.ts`、`routes.ts` 与 `site-registry.ts` 分别表达部分归属，实施时必须同步。
- 内容身份、永久内容关系、板块归属、编辑阅读顺序与本次阅读来源分别建模，不把它们压成一个 parent 字段。允许从指南引用同一个题单或问题。
- 新指南首页、基础概览/定位文章的准确内容落点需在实施计划中逐篇列出，注明复用章节或需要新写；中英文同步。目录项必须指向有实际内容的页面或锚点。
- Starlight 使用说明与普通 Astro 页面共用导航映射和目录数据；搜索元数据、阅读续接、安全返回路径白名单需要同步支持新增指南入口。
- 校验器当前强制每页六个主入口，必须更新为新的三项导航与独立搜索入口约定；保留旧路径/锚点等全量输出校验。
- 现有样式系统使用原生 Astro/Starlight 组件和 authored Icon。PRODUCT.md 中仍有旧 Radix 技术描述，属于文档漂移；本方案不据此新增依赖，技术文档同步列为实施前置。

## 9. 设计自审与问题处置

审阅方式：作者对照真实内容、路由、导航映射、目标状态与阅读返回代码完成两轮检查。此处是设计自审，不代表独立评审或浏览器验收。

| 严重程度 | 发现的问题 | 方案处理/实施要求 |
| --- | --- | --- |
| 高 | 先选择目标的首次弹窗，与“先理解模型”的阅读顺序冲突 | 改为非阻断入口；明确操作后应用目标 |
| 高 | 导航简单合并后，侧栏、面包屑与搜索仍可能保留旧六板块归属 | 单一板块映射；逐路由验证，搜索单独定义工具状态 |
| 高 | “分类放指南”只改菜单会让实际分类页仍落在另一个板块 | 本方案明确把分类页面归到指南；题库复用分类数据做筛选 |
| 高 | 候选人反向提问指南与实际 question-set 共用 collections 路由，可能被误当成题目集合生成连续阅读 | 按既有 kind 区分展示与阅读行为；指南提供交叉入口，保留一份内容身份 |
| 中 | “画像”同时指自己当前水平、目标阶段、使用场景，可能产生误导过滤 | 明确准备/评估目标；场景独立，阶段对比不改目标 |
| 中 | 将六步全部扩成新文章，会复制现有说明且产生空内容 | 先映射真实章节；“开始准备”使用行动区；新内容逐篇确认 |
| 中 | 全局方法被误标为角色专属内容 | 只组合真实方法、角色要求与题目；专属内容需另行编辑 |
| 中 | 强制顺序妨碍专家、面试官、外链访客 | 推荐顺序与直接入口并存；方法按真实使用者分段 |
| 中 | 导航收敛可能遗漏题单、本地集合、来源/许可、分析标识、AI提示工具 | 题库目录覆盖题单和本次集合；正文工具与页脚入口有单独验收 |
| 中 | 新路径不在阅读来源安全白名单，导致指南进入问题后不能正确返回 | 新路由加入同域/base/语言校验，并验证拒绝外部来源 |
| 中 | 带目标过滤的题单可能为空，用户以为内容消失 | 显示当前范围与空原因；允许返回原题单或看全部，不补入无关题目 |
| 中 | MECE 被解释为所有筛选维度互斥，或站点覆盖所有面试知识 | 仅主能力要求单一归属；交叉维度与覆盖边界明确说明 |

第一轮审查修正了分类归属、全站搜索的板块状态和“开始准备”重复文章。第二轮补齐了候选人指南类型、准备/评估目标语义、安全返回路径与现有校验器约束。剩余需要书面审阅确定的是本文的信息架构；具体文件改动和实施次序在方案通过后写入实施计划。

## 10. 实施后的验收场景

1. 新访客从首页进入指南，理解能力框架后选择岗位/目标阶段，再进入匹配题目；任一步可跳读，正文未被弹窗阻断。
2. 面试官定位被评估岗位并进入取证方法与面试官题单；晋升用户进入责任与持续结果要求；各路径动作含义明确。
3. 已有目标、明确全部、临时关闭、存储受限、链接覆盖本地目标时，指南均可阅读且状态提示准确。
4. 分类索引、能力域/叶、岗位、主题、场景页面顶栏高亮指南，目录与面包屑一致；进入题目后题库高亮，知识归属链接可回分类。
5. 题库按相同维度组合筛选；与指南链接携带的条件一致，切换目标/场景后结果与计数一致。
