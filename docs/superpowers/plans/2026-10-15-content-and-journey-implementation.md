# Interview Compass 内容与用户动线实施计划
> **Historical record:** This document records a plan or review from its date; its framework and implementation statements are not current. See the [current architecture](../../architecture/current-state.md).


> 本计划由仓库维护者在当前任务内串行执行；每批先固定可观察行为，再实现并验收。

**目标：** 按《全站内容、用户洞见与体验重组报告》完成内容语义、入口层级、问题发现、双语体验和验收记录，使不同读者能按目标找到少量相关问题、理解其证据边界并继续或返回。

**架构：** 保留 Astro 静态站点、双语内容集合、稳定 questionId 和 Pagefind。精选集、任务路径与分析都引用现有题目；题目专属分析以可选且可追踪的内容数据表达，共同规则保留在方法页与使用说明中。

**技术栈：** Astro、Starlight、TypeScript、Pagefind、Vitest、Playwright、GitHub Actions。

**依据：** `docs/reviews/2026-10-15-site-content-reorganization-report.md`，重点为 P0–P4、U01–U16、20–23 节。

## 全局约束

- 中英文题目和分析保持同一核心意图，允许语言自然差异，不机械对齐句数。
- 不提供标准答案、示范回答、自动候选人总分或录用建议。
- “证据不足，暂不评分”不能自动落为 1 分；角色、责任范围、职业轨道和阶段不可互相推断。
- 结果比较需说明口径、背景差异、替代解释、本人贡献和验证范围。
- 精选、路径和分类复用稳定 questionId，不复制题目。
- 页面保持 GitHub Pages 子路径 `/interview-compass/` 可部署、语言切换和键盘可用。

## 审查重点

- 空搜索、无结果和超多结果：提供清楚的恢复、分页及条件保留行为。
- 直接打开题目与从筛选／搜索进入：返回动作有效且不接受外部或跨语言跳转。
- 中文与英文 handbook、方法页和题卡：术语、链接、导航与主题结构一致。
- 题目专属分析缺失：显示准确的共同规则说明，不误导为逐题专家分析。
- 角色与阶段不同：不要求初级候选人回答管理题，不把工程阶段套用到所有岗位。

## 实施批次

1. **已完成（实施与浏览器覆盖）**：完整搜索结果、分页、查询保留、空状态与筛选协作；题库渐进筛选及浏览返回状态。
2. **已完成（实施与浏览器覆盖）**：handbook 统一页头、搜索、语言、容器和页脚；首页精选、任务路径、分类索引、方法页和题库形成双向入口。
3. **已完成（12 题试点）**：添加可选专属分析模型及状态；题卡、练习和公共 feed 使用一致语义；未审题目标注共用框架。
4. **已完成（路径组织）**：六类任务可执行；招聘流程含画像、轮次、主问追问、校准和复盘，并链接产品、运营、管理题；体现 IC／一线／二线管理、双向尽调和四项成长观察。
5. **持续内容编辑，不是本次发布阻塞**：目前 12 / 1,334 道题完成双语专属分析。余下题目保持诚实的“逐题分析待校准”状态；按实际使用价值增量复核，不批量生成假性专属结论。47 对中英追问条数差异需另行逐对语义校对。
6. **已完成（本次验收）**：README、PRODUCT/DESIGN、双语 handbook、配套 skill 对齐；内容、类型、单元、构建、桌面／移动浏览器测试验证，最终记录见审阅报告 §22.3、§25。

## 验收原则

每批验证它负责的用户结果，不以字段存在、页面可构建或自动测试通过代替语义复核。当前交付的验收范围是网站架构、任务动线、同步规则、12 题编辑基准及状态透明度；全库专属分析与 U16 双语差异校对是持续编辑工作，不能冒称本次已全部完成。
