# 工程师受众与业务理解拓展

日期：2026-10-16。作者最新指令覆盖先前“技术为主、产品运营并行参考”的定位。

## 产品边界

平台只服务工程师及工程管理者。公开方向：通用工程、前端、后端、客户端、AI 工程、数据工程；各自区分专业贡献与管理责任，共 36 个可选组合。通用工程不是服务端同义词，服务端使用后端入口。

产品 sense、运营工作流理解、设计协作、商业化、数据口径和项目协调是工程师的拓展能力。首页按这些能力给主题入口，招聘动线据此考察工程师的业务理解；不再显示独立产品经理、运营、设计、市场或 PMO 的求职阶段入口。

## 内容保留与责任边界

不删题，也不把所有商业题改成纯技术题。1,334 道题全部保留，同一题仍跨阶段复用。既有 A–H 主要能力保持稳定：商业案例可能主要考察 B 业务建模，也可能考察 C 判断规划或 D 执行，不能为了改定位一律移到 B。

逐题检查了原仅有非工程组合的 28 题，涉及订阅与促销经济性、投入产出、市场假设、业务退出、运营容量、审核工作流及实验归因。补充双语 `engineeringLens`，明确工程师需要理解什么，以及哪些业务批准权不应默认属于本人；按复杂度和实际责任显式登记中级／高级及以上组合，没有将初级工程师机械赋予公司经营职责。相关题面、信号和判断仍可用于案例推演，不要求捏造亲历。

- 两道原明确以一线运营或活动操盘人为回答者的题改为工程师参与／协作问法：`d-incident-campaign-outage-business-fallback`、`d-operations-campaign-budget-roi`。
- 其他 26 道保留题面；工程阅读上下文说明是业务理解与跨职能接口判断，并非要求兼任对应职能。
- 28 道题的双语岗位和职业轨道标签与新增组合同步，指纹重新核验。
- 工程阅读视角在题目页、可选 AI Prompt 和单题公共数据中一致提供，避免导出后丢失授权边界。
- 非技术岗位词汇与研究模型保留在源码中以保存来源背景，公开角色路由、菜单、筛选、阶段比较和 profile token 仅提供工程方向。旧的非工程浏览偏好视为失效，链接明确提示后允许重选。

## 用户动线与视觉

首次弹窗只需选择工程方向和目标阶段。首页先说明工程师定位，再通过产品判断、运营工作流、需求与设计协作引导拓展；求职、招聘、晋升和复盘仍是任务身份，和工程专业方向保持独立。

目标摘要与搜索及正文使用同一 1120px 容器：左侧岗位／阶段与次要题量，右侧操作链接；替换整条蓝色底色和左侧堆叠。手机自然换行，临时分享目标额外显示采用／移除动作，本地模式保持三个简短操作。沿用现有字体、颜色与图标。

## 验收口径

工程方向数、36 个组合、1,334 道题以及 28 条工程上下文应可由数据核对。严格过滤、全量浏览、双语、阶段提示和分享语义沿用原设计。新增回归验证非工程准备目标不再开放，但商业案例仍可在工程目标下阅读并生成带有工程业务上下文的 Prompt。完整检查及浏览器结果记入实施审阅，不以数据非空证明所有问题都应是必考题。
