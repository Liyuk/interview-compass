## 本项目如何借鉴：先定义问题需要打开哪种思考

这里的“考察意图”是编者希望引出的讨论方向；单个问题不应被描述为足以测定能力，也不预设读者必须作出某个选择。

建议给编辑者提供五种写题检查角度，作为内部工具，而不是强制每道题都写五遍：

| 检查角度 | 编辑问题时检查什么 | 可解释的提问目的 |
|---|---|---|
| 看清对象 | 关键名词是否明确，是否存在不同人的不同理解 | 引出对业务语义、边界与参与者的理解 |
| 说明判断 | 读者是否需要解释如何形成判断 | 引出假设、信息来源、替代解释与不确定性 |
| 落实行动 | 问题是否允许讨论行动及其条件 | 引出组织行动、推进工作与处理约束的思路 |
| 观察变化 | 是否能讨论行动之后发生什么 | 引出观察结果、辨别影响和修正计划的方法 |
| 解释经历 | 是否允许讲述实际经历及其局限 | 引出个人承担的工作与事后反思 |

这些角度来自本项目已经讨论的判断、执行、领域建模与学习要求。它们可以跨角色使用，也可以与职能专属问题并存。专业题应保留专业对象，不能把所有题目都改成泛泛的“如何思考”。

## 一张题卡需要保存什么

建议采用以下最小结构：

| 字段 | 用途 |
|---|---|
| 主问 | 展示一个清楚、可讨论的问题 |
| 为什么问 | 解释想了解什么，以及哪些能力可能相关 |
| 背景概念 | 帮读者定位需要进一步了解的知识，不要求掌握某个唯一框架 |
| 可选追问 | 延长讨论；各自有明确目的，避免替读者给出结论 |
| 适用语境 | 标记角色、责任范围和情境，让读者选择自己的入口 |
| 相关问题 | 连接另一个思考方向，而不是重复当前问题 |
| 来源说明 | 区分原创问题与引用；参考链接不能被当成复用许可 |

“为什么问”可以写成：“希望了解你如何界定问题，以及哪些信息会影响你的判断。”避免写成：“正确回答必须包括某五个步骤。”

## 通用框架与岗位框架怎么组织

沿用本项目八域作为归档框架；下面的对应关系是我们的编辑判断，不是原站对能力的定义。

| 本项目能力域 | 品牌／增长岗位中可以新增的专业语境 |
|---|---|
| A 专业解题与实现 | 研究、分析、实验及营销工具的实际使用 |
| B 业务理解与领域建模 | 客户、交易、渠道参与者与商业规则的理解 |
| C 价值判断与方向规划 | 目标选择、资源投入和方向调整 |
| D 交付执行与持续运营 | 工作推进、依赖处理、运行反馈 |
| E 协作沟通与影响 | 各方理解、分歧沟通与共同决策 |
| F 人才与组织建设 | 团队职责、人才发展与组织机制 |
| G 学习适应与持续成长 | 从经历中修正认识与工作方式 |
| H 职业责任与工作方式 | 信息披露、责任承担与工作约定 |

这张表用于指导后续原创选题，并不表示原站对八域覆盖均衡，尤其不能由出现领导力主题推定它已有完整组织管理题库。

内容组织可以采用“通用主问＋职能语境”。只有职能知识改变了提问目标时才另建题卡；如果只是换一个场景，维护同一张题卡的语境说明。一个问题设一个主要能力归属，多入口引用，避免为每个角色复制同一份正文。
