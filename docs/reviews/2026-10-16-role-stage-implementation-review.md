# 岗位分级与同题分阶段阅读：实施审阅

日期：2026-10-16。范围：阶段模型与题目阅读框架；全站个性化仍在实施中。

## 已落地

- 12 个现有岗位均可进入阶段说明，共 68 个岗位—阶段组合。工程五个入口共用原有六阶段；其他六个职能分别有六阶段，通用管理入口有两个管理阶段。
- 保留原有工程六阶段的正文、链接及责任矩阵；模型总览明确工程矩阵的适用范围，新增岗位入口。
- 产品、运营、市场、设计、数据、项目管理使用自身专业工作与产物定义要求，不通过替换“工程师”称呼复制工程标准。
- 新岗位标准每个评价维度 3–4 条；成长维度明确列出学习、自驱、思维、韧性。工程模型保留现有 3–5 条标准。
- 题目 ID、题面、来源与题量不变。所有题目页增加同题跨阶段阅读入口；选择岗位和阶段后展示责任、判断、结果、权限及证据。
- 知识解释不要求实际项目业绩；案例允许明确假设的推演；经历和作品类题核验真实行动与产物。假设验证计划不能冒充已取得的结果。
- 1–4 分仍评价相应阶段下的回答表现；初级回答可以优秀，高级头衔不自动得高分。
- 所选阶段可写入详情链接、刷新恢复、切换语言，并进入外部 AI Prompt；未选阶段时保留原有 Prompt。
- 阶段提示标明为规则生成阅读框架，不冒充逐题审核，也不宣称每道题都适用于所有可比较的阶段。
- 新选择器复用站内 Lucide chevron、12px 图标内边距与共享控件样式。

## 验证记录

- 内容校验：2668 个双语条目，1334 道已发布题。
- 单元测试：16 个文件，71 个测试通过，包含各岗位模型、同题不同阶段、无效组合和 Prompt 的回归检查。
- Astro 类型检查：无错误、警告或提示。
- 完整构建与 Pagefind：通过；搜索仍使用原有范围，尚未开启全站阶段过滤。
- 完整 E2E：103 通过，1 跳过，覆盖桌面和移动端。新增用例验证产品 IC/管理分流、阶段切换、刷新、语言切换与 Prompt。
- 使用实际浏览器检查题目阶段组件，确认视觉层级并修正新控件沿用浏览器原生箭头的问题。

## 尚未完成，不能视为整项交付

1. 全量题目的岗位—阶段适用性审核及覆盖报告。需要保留同题跨阶段的空间，只限制真实不相关的责任，不能按能力标签或项目大小机械分级。
2. 非工程岗位的 A–H 责任深度矩阵在后续批次已补齐，见下方更新；原工程矩阵保持既有内容。
3. 全站统一严格过滤、Pagefind profile token、偏好持久化、首次弹窗和右上角目标切换尚未实现。阶段内容和题目适用性审核完成前不开放首次弹窗。
4. 规则生成框架不等于逐题分阶段分析。若后续需要特定题目的独有阶段锚点，应新增经审核的覆盖条目，复用题目 ID，避免复制题目。

## 本轮判断

将“适用性”与“阶段回答要求”拆开是必要调整：前者回答该目标是否需要读这道题，后者回答读同一道题时要核验什么。当前已落地后者和岗位模型入口，尚未完成前者及全站入口。保持完整目标继续实施，不据此宣称个性化已经完成。
