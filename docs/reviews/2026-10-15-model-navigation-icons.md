# 能力模型、能力地图与图标系统审查

## 范围与结论

本次仅补能力标准、阅读组织和界面规范，不新增面试题。模型仍是本站编辑性启发草稿；A–H 是能力分类，四个模型维度是阶段评价视角。两者通过叶子能力引用连接。

原模型每种语言 72 条，每组均为最低 3 条。主要缺口是领域与数据模型、交付后的闭环、自驱与恢复，以及具体规划、绩效纠偏、组织过渡与权力约束。本次逐组补齐可区分且可观察的行为，共增加 40 条中英配对标准，达到每种语言 112 条。

## 规划必须明确

- 业务规划：C 规划、结果、投入选择；从功能里程碑，扩展到季度业务规划、年度方向与组合调整。
- 技术规划：A 工程体系与系统设计，并关联 B 模型演进；从模块方案扩展到领域路线图、跨团队演进与组织投资治理。
- 团队规划：F 团队设计、培养、继任，并关联 D 容量；从项目能力缺口扩展到招聘培养、编制、管理跨度与继任供给。

规划的最低可观察结构是目标/假设、现状/差距、取舍/不做、资源/依赖、里程碑/结果验证、调整/退出条件。初级参与理解与执行，不要求独立拥有组织规划。

## 阶段 × A–H 矩阵

数值是责任深度的四档显示标签，不是测得的掌握百分比、时间分配、权重或 1–4 面试得分，行不归一化。25% = 指导下应用；50% = 独立处理常见问题；75% = 复杂/跨团队问题并带动他人；100% = 组织或关键领域机制建设。

每个值是可调整的编辑建议，不能由题量、标准条数或引用频次推算，也不代表任何公司校准标准。跨岗位只比较相关叶子；管理者 A/B 看专业评审和治理，非个人编码深度。F 对 IC 看辅导、负责人供给和组织协作，不强加绩效管理。诚信、安全、贡献归属在所有阶段均是底线。

## 阅读组织

能力域页只展示每类前三题，并提供完整分类入口，预览不等于优先级。叶子页按已有题型唯一归组：概念与边界 → 判断与方案 → 实现与验证 → 经历与复盘；缺题型归开放探索。一题多格式时按以上顺序选第一组，不重复展示。每组按八题分批，只有首组首批默认展开，其余使用原生 details，支持无 JavaScript、键盘和浏览器页内查找。

这是阅读顺序提示，不宣称题目存在真实因果或难度关系。真正的题目递进、先修与优先级还需逐题编辑，不能从展示顺序自动得出。

## 功能图标选型

| 方案 | 官方事实 | 本项目取舍 |
| --- | --- | --- |
| [Radix Icons](https://www.radix-ui.com/icons) | 15×15 图标，官方 React 组件，MIT | 紧凑控件适合；与当前 24px SVG 图标基底不同 |
| [Lucide for Astro](https://lucide.dev/guide/astro/) | Astro 组件输出内联 SVG，支持尺寸、颜色、按需引入 | 选用；无需为图标引入 React 岛，统一搜索、箭头与展开图标 |

选定 @lucide/astro，静态按图标路径导入，由 Icon.astro 封装名字与规范。统一 24×24 源网格、1.75 描边、currentColor、常用显示尺寸 16/18/20/24px。装饰图标对读屏隐藏；有意义图标提供可访问名称。方向关系文字中的箭头保留文本语义。

品牌罗盘为独立 SVG：保留深色轮廓、红色方向指针和衬线字标，指针向东北倾斜。站内 Logo 用 48px 源画布；favicon 使用简化的 32px 画布与暖白底以适应深浅浏览器标签。小图删除刻度和中心圆点，避免缩小时糊成团。

## 控件规范

原生 select 保留语义、系统弹层与键盘行为，appearance:none 仅移除浏览器自绘箭头。用共享 Lucide ChevronDown 绝对定位，40px 控件高、12px 左右视觉内边距、16px 箭头、40px 文字右侧保留区域。箭头 pointer-events:none，点击可穿透；forced-colors 下恢复系统箭头；focus-visible 保留轮廓。此几何是本站选定规范，不声称是某个设计系统的强制值。
