# 用户动线与题目分析审计

审计日期：2026-10-15。范围：主导航、首页入口、题目发现路径，以及已发布中文题目与双语题卡分析结构。结论基于代码、全库 frontmatter 统计和 A–H 各域样本审读；本轮没有开展真实用户访谈或可用性测试，因此用户路径结论属于待验证的启发式判断。

## 结论

题库的多维入口是合理的，但主导航此前把能力分类和阶段模型放在岗位、场景之前，而且没有“主题”直达入口。大多数读者首先带着具体搜索词、技术主题、目标岗位或面试/晋升任务而来；阶段能力模型更适合在其后作为参考。因此主导航调整为“面试题库 → 主题索引 → 岗位导航 → 使用场景 → 能力地图 → 阶段能力”，六项均为四字中文标签。首页保留搜索和四种入口，把短的跨域阅读路径放在完整 A–H 分类树之前。

题卡内容并非全都经过逐题的客观分析。全库题目都有各自的题干、考察意图和观察信号，611 道还有专属追问；但题目详情中的“客观问题”目前直接重复题干，“进一步推论”由同一模板拼接意图、首个信号和能力名，默认上下文问题、决策说明、收益与成本提示也复用全站通用文本。四档 rubric 的定义同样共用，只在部分证据锚点里替换观察信号。因此目前只能说核心意图与信号大多针对题目，不能说每张题卡的完整分析都已针对题目逐条校准，也不能把这些参考当作有效度已经验证的客观评分标准。

## 全库结构核验

扫描 992 道已发布中文题目；中英文各有对应记录，题库仍为 992 个 questionId：

| 项目 | 数量 | 说明 |
| --- | ---: | --- |
| 有考察意图 | 992 / 992 | 每题均有独立意图文本；是否精准对应题干仍需审读 |
| 有观察信号 | 992 / 992 | 信号字段逐题存在；个别题有语义重叠 |
| 有额外追问 | 611 / 992 | 381 道没有题目专属追问，会落到通用上下文问题 |
| 有题目专属客观问题字段 | 0 / 992 | 当前“客观问题”来自题干原文 |
| 有题目专属推论/上下文决策/收益/成本字段 | 0 / 992 | 由 `question-evaluation.ts` 使用共享模板生成 |
| 有题目专属背景材料 | 0 / 992 | frontmatter 中没有 `background` 内容 |

八个能力域各抽取一题审读题干、意图、信号及追问。题目语境与意图大体相关；但“指标与因果”“市场经济”“事故恢复”“冲突验收”“管理诊断”“职业边界”等题目都展示相同的通用决策和利弊提问，无法据此声称页面呈现的是逐题专家分析。对全部 992 题的检查是字段覆盖与生成逻辑审计，不是逐题人工语义校准。

抽样发现 `a-ai-engineering-agent-duplicate-side-effect` 的中英文信号都存在近义重复：两条都在描述幂等键/状态查询/结果确认；英文还重复了模型新决策与网络重试、未知状态下的暂停交接。本轮已合并这些重复点，并保留不同证据边界。当前校验能查双语字段一致与缺失，但不检查近义重复，后续仍需编辑审读。

## 面向读者的路径

| 读者当下的任务 | 直接入口 | 后续路径 |
| --- | --- | --- |
| 记得关键词或问题片段 | 全站搜索 / 面试题库 | 题目 → 追问、观察信号与评估参考 |
| 想按主题准备 | 主题索引 | 主题 → 题目 → 相关能力 |
| 为某个职能岗位准备 | 岗位导航 | 岗位 → 题目按能力归组 → 按场景缩小范围 |
| 设计面试、晋升或自我复盘 | 使用场景 | 场景指南 → 责任范围/职业轨道筛选 → 题目 |
| 还不清楚要查什么 | 首页的跨域路径、能力地图 | 阅读路径 → A–H 域 → 叶子能力 → 题目 |
| 对齐阶段责任要求 | 阶段能力 | 专业/管理发展路线 → 阶段标准 → A–H 能力叶子 |

当前页面仍有两个需要继续观察的负担：问题库会直接呈现全部匹配题目；岗位与场景页按能力分组，但列表较长。后续可根据真实使用反馈增加组内折叠/分批或筛选项搜索，不应只因题量大就多造导航层级。首页先展示少量路径，再展示完整 A–H 树，降低初次进入时的扫描成本。

这次导航调整依据的是任务优先与标签可理解性：导航标签应让人预期点击后能找到什么；端到端任务则适合用有逻辑顺序的路径呈现。参考：[NN/g：Information Scent](https://www.nngroup.com/articles/information-scent/)、[GOV.UK：Step-by-step navigation](https://design-system.service.gov.uk/patterns/step-by-step-navigation/)。这些来源提供设计原则，不代表已在本项目用户群中验证。

## 后续内容修订规则

1. 将“客观问题”写成题干背后的现实决策或待解决状态，不复制题干；经历题则明确待核实的责任、影响和学习事实。
2. 将“可能的推论”标为假设，并写出至少一种替代解释及需要的反证；禁止由单条信号直接推断人格、能力或诚信。
3. 优先补题目专属追问：目标/基线、约束/责任边界、备选方案、受影响者、验证证据中，只保留对该题有区分力的上下文。
4. 决策、收益和成本围绕题干中的实际目标与方案展开；没有具体方案时，呈现需要候选人比较的维度，不伪装成题目已有结论。
5. 四档评分继续作为启发式证据锚点；分别校准到岗位、阶段与责任范围，说明可观察行为，并避免把一次面试回答等同于稳定人格或整体能力。
6. 逐题修订时先合并重复信号、检查意图是否可由答案证据支持，再校对中英配对。规模化回填前，应先做一小组跨 A–H 的编辑试点并复核。

## 证据边界

本审计没有声称面试评分具备心理测量效度、评分者一致性或预测工作绩效的效度。要做这类结论，需要有明确定义的岗位能力模型、经校准的面试官、样本数据及一致性/结果验证；当前站点的评分说明是帮助提问和观察的启发式参考。
