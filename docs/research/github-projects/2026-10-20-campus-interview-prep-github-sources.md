## How these sources map to guide topics

- **OS, networking, computer architecture, databases:** Start with the subject map and topic files in [CS Fundamentals Interview](https://github.com/JayrajSinh16/CS-Fundamentals-Interview); use [Coding Interview University](https://github.com/jwasham/coding-interview-university) for adjacent concepts such as processes/threads, caches and testing. Neither is a complete substitute for a databases course or for checking current implementation specifics.
- **Software engineering and design:** Use the study-plan references to testing and design patterns, then make learners explain a design in their own project context. The project-deep-dive guide supplies prompts about rationale and alternatives; it is not a full software engineering curriculum.
- **Project storytelling / trade-offs:** Use the progressive project-deep-dive questions from [Alexey Grigorev's guide](https://github.com/alexeygrigorev/ai-engineering-field-guide/blob/main/interview/questions/03-project-deep-dive.md): problem and user, personal role, constraints, decision, alternatives, cost, result, and what changed or remains uncertain.
- **Collaboration, conflict and setbacks:** Build a small story bank from real experiences; the [new-grad handbook](https://github.com/zapplyjobs/interview-handbook-2026) supplies prompt categories and suggests concise CAR framing. A difficult result can still be discussed as an adaptation/learning story; candidates should not invent a success or memorize the repo's sample script.
- **Knowledge transfer:** The [DPP guide](https://github.com/DPP-2026/dpp-interview-prep/blob/main/07-behavioral-realtime.md) suggests evidence such as documentation, pairing, explaining why, or helping another person get oriented. Present these as possible examples, not expectations that every student has mentored someone.
- **Career narrative:** The new-grad handbook includes motivation and values prompts. A preparation guide can ask candidates to connect their interests, course/project choices, and next learning goal to the specific role, without prescribing one “correct” career story.

## Source-use notes

- These are community-maintained GitHub sources, not employer-owned interview policies. Avoid claims such as “companies always ask” based on these repositories alone.
- License status above was read from each repository's GitHub API metadata on the review date. A missing detected license is not permission to republish repository content; link to the original and write original summaries/prompts.
- The starred counts and push dates are time-bound repository metadata, not quality ratings. Recheck before a later publication.
