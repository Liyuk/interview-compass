title: What does it mean when users repeatedly bypass the main flow?
question: >-
  Analytics show target users skipping the product's main flow and using exports, spreadsheets, or manual
  coordination instead; the team believes this is a user-habit problem. How would you decide whether the
  product conflicts with real work practices?
intent: Assess judgment about user workflows, alternatives, and where product value is realized.
signals:
  - Studies the full task chain and constraints behind user workarounds.
  - Tests whether entry points, permissions, collaboration, or data migration create extra effort.
  - Validates prioritization through task completion, errors, and switching costs.
  - >-
    Define the target users, outcome to change, baseline, and guardrails for “Users frequently bypass the
    primary flow.”
  - >-
    Compare alternatives by value, causal evidence, resource needs, and opportunity cost, including what to
    defer.
  - Set signals for continuing, adjusting, expanding, or stopping, and explain how to verify the result.
  - Observe triggers and costs of workaround behavior.
  - Interview different roles and verify where rules originate.
  - Compare a patch, process change, and domain-model redesign.

  - What evidence distinguishes a sensible expert shortcut from a product defect?
  - If a workaround completes the task faster, should the product still eliminate it?

  - How should requests from a few high-value customers be separated from widespread problems?
  - How would you verify a redesign reduces offline work?
