title: How do you keep settlements traceable after partial refunds and commission rule changes?
question: >-
  An order has been split between a channel and creator. Later, the customer returns only some items
  and the commission rule changes. How would you represent the original transaction, refund,
  commission reversal, and rule version so each settlement can be reproduced and reconciled?
intent: >-
  Assess whether you model refunds and rule changes as traceable business events and explain
  attribution, recomputation boundaries, and reconciliation without overwriting historical results.
signals:
  - >-
    Defines stable links, amount grain, and state changes for the original order, refund event,
    split, and reversal.
  - >-
    States the effective time of a commission rule, the boundary between carrying forward or
    recomputing historical transactions, and handling refunds across settlement periods.
  - >-
    Designs a traceable ledger that reproduces the original settlement under the rule then in effect
    and separates facts, inferences, and later adjustments.
  - >-
    Uses partial refunds, rule changes, and missing details to test reconciliation, idempotency, and
    exception explanations.
