title: High activity does not equal high value
question: >-
  A feature is used often but has not improved retention or payment. How would you determine whether it
  creates core value, reflects habit, or rewards the wrong behavior?
intent: >-
  Assess how you handle “High activity does not equal high value”: clarify goals and constraints, make an
  evidence-based judgment, and explain how you would verify outcomes and trade-offs.
signals:
  - >-
    Define the target users, outcome to change, baseline, and guardrails for “High activity does not equal
    high value.”
  - >-
    Compare alternatives by value, causal evidence, resource needs, and opportunity cost, including what to
    defer.
  - Set signals for continuing, adjusting, expanding, or stopping, and explain how to verify the result.
  - Separates feature usage from task completion quality and longer-term user outcomes
  - Proposes evidence that distinguishes learning cost, interaction friction, and user mismatch
  - Explains what findings would lead to keeping, revising, or reversing the redesign
  - Inspect distributions across users and task complexity.
  - Distinguish more completions from worse completion experience.
  - Propose segmented rollback and revalidation by user, task, or stage.
  - Segments changes by user type and core task instead of reporting only an average
  - Sets falsifiable conditions for continuing, rolling back, or testing in stages
  - Distinguishes clicks, use, task completion, and user outcomes as different evidence.
  - Checks user segments, motivations, and unresolved task barriers.
  - >-
    Compares the cost of fixing, repositioning, or retiring the feature and defines the next validation
    criteria.
