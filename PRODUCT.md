# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Astro 7 static site, with bilingual Chinese-default/English routes, Pagefind search, shared CSS tokens and native accessible HTML controls, and GitHub Actions deployment to GitHub Pages.

## Users

Engineers preparing for interviews and promotion, interviewing other engineers, and growing into technical leadership. Public targets are general software engineering, frontend, backend, mobile, AI engineering, and data engineering. Product, operations, design, commercial, and project-management material develops engineers’ business understanding and collaboration; these are not independent target jobs.

## Product Purpose

Interview Compass is a question-first, heuristic library. Visitors start from a goal, search directly, or browse by topic, role, responsibility, and capability. Questions help readers compare approaches, examine context and causality, and surface verifiable contribution. The site guides inquiry; it does not supply model answers.

## Positioning

The core unit is a question with its purpose, organized through both shared capability frameworks and role-specific frameworks. A question can be reached through multiple independent views such as capability, role, topic, responsibility scope, and interview context.

## Operating Context

The main entry paths are direct question search and topic browsing. A task-first path helps candidates, interviewers, promotion candidates and reviewers, people practicing, and teams reviewing projects. Exploration stays within engineering specializations and professional/engineering-management stages. Cross-functional cases remain available as engineering expansion capabilities, with explicit contribution and authority boundaries. No cross-functional source material is discarded merely because the audience is narrower.

## Capabilities and Constraints

- Questions are the primary content. Explain the objective problem, purpose, context to establish, possible interpretations, comparisons, decision considerations, and evidence that could support a judgment.
- Show shared 1–4 evidence anchors and clearly distinguish them from the smaller set of individually reviewed question analyses. Never imply an unreviewed template is a question-specific conclusion.
- Do not provide model answers, automatic scoring, aggregate candidate scores, or hiring recommendations.
- General frameworks and role-specific frameworks coexist; cross-link questions rather than duplicating them for each entry path.
- Include technical foundations, role skills, engineering practice, domain modeling, product and end-to-end thinking, delivery and management, operations, and professional growth.
- Use shared CSS tokens, the authored Icon sprite, and native links, buttons, details, dialogs and selects as the interface baseline. Keep every routed page on the shared Astro shell and control system; do not mix unrelated component styles or add decorative patterns without a product reason.
- Deployment target is GitHub Pages; the design should work as a static site unless a demonstrated requirement changes that constraint.
- External reference material is research input. Preserve attribution and license boundaries; do not publish archived source snapshots as site content.

## Brand Commitments

Use the name “Interview Compass.” The site is a practical, question-led reference rather than an answer book.

## Product Principles

- Make questions easy to search and explore.
- Ship Chinese and English from the first release, with a visible language switch that stays on the corresponding page when a translation exists.
- Explain what a question is meant to surface, without prescribing an answer.
- Center comparisons, challenging goals, execution, measured outcomes, contribution and attribution; help readers find and substantiate highlights.
- Use learning, self-direction, thinking, and resilience as cross-cutting growth lenses.
- Separate shared capability frameworks from role-specific knowledge while allowing useful cross-links.
- Keep classification dimensions independent so one question can appear in several relevant views.
- Make sources and content provenance traceable.

## Preparation and discovery

Primary navigation is Home, Preparation guide and Question bank. Global search is a persistent utility. The guide organizes getting started, capabilities, preparation direction, role expectations, methods and classification; question browsing reuses the same independent facets. The guide recommends a reading sequence and supports direct entry. Targets mean the role and responsibility being prepared for or assessed; context remains an independent filter.
